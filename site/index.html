The Problem We Solve

AI agents don't get hacked. They get borrowed.

An agent is given access to systems nobody has scoped. It ends up holding ninety-four permissions and using six. The other eighty-eight are not unused. They are available to anyone who can reach the agent. We identified six root causes — and built enforcement for each.

01 — Over-Permissioning

Root Cause

Nobody Knows What An Agent Actually Needs

Scoping permissions per task is slow, so teams grant broad access and move on. The agent holds ninety-four permissions and uses six.

Learned Least-Privilege. We observe actual behaviour, derive the minimum each task requires, and enforce it on every call.

02 — Prompt Injection

Root Cause

The Agent Cannot Tell Instructions Apart

An attacker's instruction hidden inside a document reads exactly like a legitimate task. The agent obeys, using access it was properly granted.

Capability Removal. The permission was never there, so the instruction has nothing to invoke.

03 — Composition

Root Cause

Safe Permissions, Dangerous Together

Reading customer records is fine. Calling an external webhook is fine. Together they are an exfiltration channel, and no identity system flags either one.

Reachability Analysis. We evaluate combinations, not individual grants.

04 — Delegation

Root Cause

Authority Widens As It Passes Down

In a chain of agents, each hand-off can grant more than it received. By the third agent, nobody can say what authority exists.

Monotonic Attenuation. Every delegated capability is equal to or narrower than its parent.

05 — Unverified Output

Root Cause

Nobody Checks What The AI Said

An AI answers from company documents. Nobody knows which document, or whether the answer held, until someone acts on a wrong one.

Verified Knowledge Systems. Every answer carries its source. When retrieval finds nothing, the system says so.

06 — Unbounded Automation

Root Cause

Departments Automate Without A Stated Limit

Vendors promise full autonomy. Legal accountability requires a named human. The gap surfaces after the money is spent.

AI-Native Transformation. The autonomy ceiling is agreed in writing before anything is built.

The Platform

One control plane. Six enforcement layers.

It sits between your agent and everything it can reach — your model provider, your MCP servers, your APIs, your database. Every call is checked against the authority that agent actually holds. Decisions return in under a millisecond.

01

Learned Least-Privilege

Static policies cannot keep up with agents whose tools change weekly. We learn task classes from observed execution, derive the capabilities each genuinely requires, and generate a candidate policy. A human approves it before it takes effect.

02

Composition & Reachability Analysis

Permissions are evaluated in combination, not one at a time. We map which capability pairs create a reachable path to data movement, credential access or irreversible action — and block the path rather than the individual grant.

03

Monotonic Delegation

When one agent hands work to another, the delegated authority is verified to be equal to or narrower than its parent. Authority can shrink down a chain. It can never grow.

04

Provenance & Taint Tracking

We track where an agent's context came from. The more untrusted material it has read — external documents, web content, other agents' output — the narrower its authority becomes, automatically. Exposure attenuates permission.

05

Poisoning-Resistant Policy Learning

A system that learns from behaviour can be taught the wrong thing. An attacker feeding synthetic activity during the learning window could permanently widen a policy. We detect, down-weight and filter suspicious observations before they influence anything.

06

Runtime Verification

At the moment of the call, the delegation chain, the declared intent, the provenance state and the capability set are verified together. The answer is allow, escalate to a human, or deny — with the reason recorded.

How It Works

Four steps. Nothing enforced until you approve it.

Shadow mode runs first. You see what your agents actually hold before anything changes — and you decide whether to enforce it.

01

Observe

The control plane runs in shadow mode alongside your agents. No enforcement, no risk. We record which capabilities each task actually invokes, and which sit unused.
Two weeks · Output: the gap between held and used

02

Derive

From observed behaviour we generate a candidate least-privilege policy per task class, plus the composition paths that exist today but should not. Suspicious observations are filtered before they influence the policy.
Output: a proposed policy and a list of reachable risks

03

Approve

A named human reviews and approves the policy. Nothing is enforced automatically. Policies are versioned, and every change carries an owner and a timestamp.
Output: an approved, versioned, attributable policy

04

Enforce

Every call is verified against the approved policy at runtime. Denials are logged with the reason. When an injected instruction arrives, the agent attempts the action and fails — because that capability was never granted.
Sub-millisecond decisions · every outcome recorded

Why enforcement rather than detection. Any defence that works by recognising an attack loses to an attack it has not seen. Removing the capability does not depend on recognition — if the permission was never granted, no instruction can invoke it, however it is phrased.

Common Questions

Answered plainly.

Agent authority enforcement limits what an AI agent can do by granting only the permissions its task requires, verified at runtime. Unlike detection-based security, which identifies and blocks malicious instructions, enforcement removes the capability entirely — so an injected instruction has nothing to invoke.

Detection works by recognising an attack pattern, which fails against attacks it has not seen. Capability removal does not depend on recognition. If a permission was never granted, no instruction can invoke it, regardless of how the instruction is phrased or hidden.

Two permissions can each be safe individually and dangerous together. Reading customer records is routine. Calling an external webhook is routine. Combined, they form an exfiltration path. Identity and access management systems evaluate permissions one at a time and do not flag the combination.

Authorisation decisions return in under a millisecond. The control plane sits in the call path, not the reasoning path — it does not add a model round trip.

Shadow mode runs alongside your agents with no enforcement, so there is no operational risk. You receive a report showing which permissions each agent holds versus uses, and every composition path that could move data out. You then decide whether to enforce.

It is the right question, and it is the reason policy learning is not left unguarded. Suspicious observations are detected, down-weighted and filtered before they influence a policy, and every generated policy requires human approval before it takes effect.

An autonomy ceiling is the honest upper limit on how much of a department's work can be automated, stated before an engagement begins. It describes the share of work hours automated, not decision authority — decisions remain with named humans. Our published figures are estimates from task-level analysis, revised as engagements complete.

The enforcement system runs with sub-millisecond decisions and a passing test suite, and the injection-blocking path works end to end. It has not yet been deployed in a customer's production environment. We will say so until it has.
