The Platform

One control plane. Six enforcement layers.

It sits between your agent and everything it can reach — your model provider, your MCP servers, your APIs, your database. Every call is checked against the authority that agent actually holds. Decisions return in under a millisecond, and every denial is recorded with its reason.

Where it sits

      │  every tool call, every model call
      ▼
  ┌─────────────────────────────────────────┐
  │   STARTIQOS CONTROL PLANE               │

No agent code changes. The control plane is a transparent proxy. You point your agent at it with one configuration line. It does not modify prompts, does not add a model round trip, and does not require your framework to support anything specific.

The Six Layers

What each layer actually does.

Each layer answers a question the others cannot. Together they define what an agent is permitted to do.

01

Learned Least-Privilege

Static policies cannot keep up with agents whose tools change weekly. We learn task classes from observed execution, derive the capabilities each genuinely requires, and generate a candidate policy. A named human approves it before it takes effect.

02

Composition & Reachability Analysis

Permissions are evaluated in combination, not one at a time. We map which capability pairs create a reachable path to data movement, credential access or irreversible action — and block the path rather than the individual grant.

03

Monotonic Delegation

When one agent hands work to another, the delegated authority is verified to be equal to or narrower than its parent. Authority can shrink down a chain. It can never grow, even if a downstream agent is fully compromised.

04

Provenance & Taint Tracking

We track where an agent’s context came from. The more untrusted material it has read — external documents, web content, other agents’ output — the narrower its authority becomes, automatically. Exposure attenuates permission.

05

Poisoning-Resistant Policy Learning

A system that learns from behaviour can be taught the wrong thing. An attacker feeding synthetic activity during the learning window could permanently widen a policy. We detect, down-weight and filter suspicious observations before they influence anything.

06

Runtime Verification

At the moment of the call, the delegation chain, the declared intent, the provenance state and the capability set are verified together. The answer is allow, escalate to a human, or deny — with the reason recorded in an append-only ledger.

Deployment

It runs inside your environment.

Traces and enforcement stay within your boundary. Security teams do not route agent tool calls through a third party, and we do not ask them to.

Self-hosted

Single Binary

One binary and one configuration file, deployed in your VPC or cluster. No inbound connection from us, no dependency on our availability.

Failure mode is configurable. Fail-open or fail-closed, per agent.

Data

Nothing Leaves

Traces record argument shapes and types, never argument values. Your data is not in the telemetry by construction, not by policy.

Anonymisable by design. This is a schema decision, not a setting.

Performance

Under A Millisecond

Token verification is offline — no callback to an issuer, no network hop in the decision path. Written in Rust for this reason.

Benchmarks published. We will not ask you to take latency on trust.
