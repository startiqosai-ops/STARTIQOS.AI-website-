Layer 04

The more it reads, the less it may do.

An agent that has processed ten external documents is a different risk from one that has read only internal records — even though it is the same agent, with the same profile. We track where an agent’s context came from, and narrow its authority as untrusted exposure accumulates. No detection, no classification. Just a smaller permission set.

Taint in a single session

  step 1   read internal ticket                  taint 0
  step 2   query ledger                          taint 0     ✓ allowed
  step 3   fetch attached PDF (external origin)  taint 2
  step 4   query ledger                          taint 2     ✓ allowed
  step 5   send email                            taint 2     ✗ DENIED

           report.send has max_benign_taint: 0
           observed only at taint 0 across 120 sessions
The capability was in the profile. Sending email is legitimate work for this agent. What changed is that it had just read something from outside the boundary — and the profile records that this capability was never once exercised after untrusted exposure.

How Taint Accrues

Not everything is equally untrusted.

Taint is a graded property, not a binary flag. A signed internal document and an arbitrary web page are not the same input.

0

Internal, structured

Database rows, internal API responses, records the organisation controls end to end. No taint.

1

Internal, authored

Wiki pages, tickets, internal documents written by people. Trusted, but a human wrote the contents and a human can be socially engineered.

2

External, identified

Email from a known correspondent, a supplier’s document, a partner’s API response. The origin is known; the contents are not controlled.

3

External, arbitrary

Web pages, unsolicited email, uploaded files, tool descriptions from an MCP server you do not operate. Assume the contents are adversarial.

Taint is monotonic within a session. It rises and does not fall. An agent cannot cleanse its context by reading something trustworthy afterwards, because the untrusted instruction is still in the context window.

Why This Beats Detection

The attack does not have to be recognised.

Injection detection asks: is this instruction malicious? Taint attenuation asks a different question entirely — has this agent been exposed to anything it should not act on?

Detection

Requires Recognition

A classifier blocks what resembles a known attack. Rephrase the instruction, encode it, split it across two documents, and the resemblance disappears.

Loses to novelty. Structurally, not occasionally.

Attenuation

Requires Nothing

We do not read the instruction or judge it. We observe that untrusted material entered the context, and narrow what the agent may do next.

Works against attacks nobody has seen, including ones that do not exist yet.
